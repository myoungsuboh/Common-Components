# ADR-2026-07-31-grid-cell-url-allowlist: 셀 URL 화이트리스트 검사

- 기록일: 2026-07-31 11:48
- 상태: 승인됨
- 단계(Origin): dev (execute-dev)
- 관련 spec: 없음
- 관련 plan: 없음

## 맥락 (Context)

`image`·`link`·`file` 셀 타입을 추가하면서 셀 값을 `img.src`, `a.href`에 넣게 되었다. 그리드 데이터는 서버 응답이나 사용자 입력(엑셀 업로드 포함)에서 오는 경우가 대부분이다. 값이 `javascript:alert(1)` 같은 스킴이면 링크 클릭 시 스크립트가 실행된다. 값을 그대로 대입하면 이 경로가 열린다.

## 결정 (Decision)

`safeUrl()` 헬퍼로 URL을 검사한 뒤에만 `src`/`href`에 대입한다. 허용 대상은 `http:`, `https:`, `mailto:`, `data:image/`, 그리고 스킴이 없는 상대경로다. 그 외(`javascript:`, `vbscript:`, `data:text/html` 등)는 빈 문자열을 반환해 요소를 아예 렌더하지 않는다.

## 고려한 대안 (Alternatives)

| 대안 | 장점 | 단점 | 채택 여부 |
|------|------|------|-----------|
| 화이트리스트 검사(`safeUrl`) | 알려지지 않은 위험 스킴까지 기본 차단(기본이 거부) | 특이한 스킴(`tel:`, `ftp:` 등)을 쓰려면 목록을 넓혀야 함 | 채택 |
| 블랙리스트 검사(`javascript:` 등만 차단) | 기존 데이터가 그대로 통과 | 우회 변형(대소문자·공백·인코딩)과 신규 스킴을 놓침 | 기각 |
| 검사 없이 그대로 대입 | 구현 없음 | 서버·업로드 데이터로 스크립트 실행 경로가 열림 | 기각 |
| 새니타이즈 라이브러리 추가(DOMPurify 등) | 검증된 구현 | URL 스킴 검사 한 가지를 위해 의존성을 추가하는 것은 과함(공통 규칙: 한 줄 로직에 패키지 추가 금지) | 기각 |

## 근거 (Rationale)

포맷터가 HTML 문자열이 아니라 `HTMLElement`를 반환하도록 설계했으므로 태그 삽입 경로는 이미 막혀 있다. 남은 구멍은 URL 속성이었고, 그 부분만 좁게 막는 것이 적절하다. 화이트리스트를 택한 이유는 기본이 "거부"여야 새 스킴이 생겨도 안전하기 때문이다. `data:image/`만 허용하고 `data:text/html`은 막은 것도 같은 이유다 — 이미지 인라인은 실용적 필요가 있지만 `data:text/html`은 스크립트 실행 경로다.

검증으로 `javascript:`, `vbscript:`, `data:text/html`이 차단되고 `https:`, 상대경로, `data:image/png`가 통과함을 확인했다. 이미지·링크 포맷터가 위험 URL을 받으면 요소를 렌더하지 않는 것도 확인했다.

## 영향 (Consequences)

- 긍정: 서버·엑셀 업로드 데이터로 인한 스크립트 실행 경로가 닫힌다. 의존성 추가가 없다.
- 트레이드오프/비용: 허용 목록에 없는 스킴(`tel:`, `ftp:` 등)은 링크가 렌더되지 않는다. 값이 조용히 사라지므로 사용자가 원인을 모를 수 있다.
- 후속으로 따라오는 결정·제약:
  - **URL을 `src`/`href`에 대입하는 새 셀 타입을 추가할 때 `safeUrl()`을 반드시 거친다.**
  - 스킴을 넓힐 필요가 생기면 화이트리스트에 추가하되, 블랙리스트 방식으로 바꾸지 않는다.
  - 차단된 URL이 조용히 사라지는 문제가 실사용에서 불편해지면, 개발 모드 콘솔 경고를 추가하는 것을 검토한다(현재는 없음).
