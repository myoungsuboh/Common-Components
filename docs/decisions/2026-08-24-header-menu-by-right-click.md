# ADR-2026-08-24-header-menu-by-right-click: 컬럼 헤더 메뉴는 우클릭으로 연다

- 기록일: 2026-08-24 06:09
- 상태: 승인됨
- 단계(Origin): dev (execute-dev)
- 관련 spec: 없음
- 관련 plan: 없음

## 맥락 (Context)

SlickGrid 헤더에는 우측 상단 그리드 메뉴(☰)와 컬럼별 헤더 메뉴(∨) 두 컨트롤이 있다. ∨ 버튼은 `position: absolute; right: 3px; width: 22px` 로 **각 컬럼의 우측**에 뜨고, ☰ 버튼은 **헤더 영역 전체의 우측**에 뜬다. 즉 맨 오른쪽 컬럼에서는 두 버튼이 같은 자리를 놓고 겹친다. 실제 화면에서 마지막 컬럼이 좁아지면 컬럼명이 `사...` 로 잘리고 그 옆에 ∨ 와 ☰ 가 나란히 붙어 있어 무엇을 누르는 것인지 알 수 없었다.

동시에 헤더 우클릭에는 이미 다른 메뉴가 걸려 있었다. 라이브러리 전역 기본값이 `enableColumnPicker: true` (`global-grid-options.js`) 라서, 우리가 아무 설정을 하지 않아도 헤더를 우클릭하면 컬럼 표시/숨김 목록(ColumnPicker)이 열린다. 결과적으로 "컬럼 숨기기" 에 도달하는 경로가 ∨ 메뉴 / 우클릭 선택기 / ☰ 목록 세 개로 흩어져 있었다.

`enableGridMenu` / `enableHeaderMenu` 도 같은 이유로 기본값이 `true` 다. 즉 `grid-menu` prop 을 주지 않아도 ☰ 와 ∨ 는 나타난다 (실측 확인).

## 결정 (Decision)

1. **컬럼 헤더 메뉴의 진입점을 헤더 우클릭으로 바꾼다.** `grid.onHeaderContextMenu` 를 받아 그 컬럼의 헤더 메뉴를 연다 (`SlickGrid.vue` `handleHeaderContextMenu`).
2. **∨ 버튼은 `visibility: hidden` 으로 숨긴다.** `display: none` 은 쓰지 않는다 — 라이브러리가 메뉴 위치를 이 버튼의 `getBoundingClientRect()` 로 계산하므로(`menuBaseClass.js` `repositionMenu` → `getOffsetRelativeToParent`) 박스가 사라지면 메뉴가 그리드 좌측 상단(0,0)에 뜬다.
3. **메뉴는 숨긴 버튼의 `click()` 을 호출해서 연다.** `createParentMenu()` 를 직접 부르지 않는다.
4. **`enableColumnPicker` 를 BASE_OPTIONS 에서 `false` 로 고정한다.** 우클릭의 주인이 둘이 되지 않게 한다. 단 2층(`:options`)에서 다시 `true` 로 켠 프로젝트에서는 우클릭을 선택기에 양보하고 우리 핸들러가 빠진다.
5. **☰ 는 그대로 둔다.** 겹침은 ∨ 를 숨기는 것으로 해소되고, ☰ 안의 컬럼 표시/숨김 목록은 GridMenu 가 자체 섹션으로 그리므로(`hideColumnPickerSection`) 4번의 영향을 받지 않는다. 숨긴 컬럼을 되살리는 경로는 여기다.
6. **컬럼명 우측 여백(`padding-right: 20px`)은 유지한다.** ∨ 가 사라져도 마지막 컬럼에는 ☰ 가 그대로 떠 있어서, 여백을 지우면 그 컬럼명이 ☰ 아래로 파고든다.

## 고려한 대안 (Alternatives)

| 대안 | 장점 | 단점 | 채택 여부 |
|------|------|------|-----------|
| ∨ 를 숨기고 우클릭으로 같은 메뉴를 연다 | 컨트롤이 겹치지 않고, 컬럼별 기능(정렬·숨기기·고정)의 진입점이 하나로 모인다. 헤더가 깨끗해진다 | 우클릭은 눌러봐야 아는 조작이라 발견성이 낮다. 안내 문구가 필요하다 | 채택 |
| ∨ 는 두고 마지막 컬럼에서만 숨긴다 | 다른 컬럼의 발견성을 유지 | "마지막 컬럼" 은 컬럼 순서변경·숨김·고정에 따라 계속 바뀐다. 그 컬럼만 메뉴를 못 쓰게 되어 동작이 컬럼마다 달라진다 | 기각 |
| ☰ 를 없애고 ∨ 만 남긴다 | 겹침이 근본적으로 사라진다 | ☰ 에만 있는 기능(필터 전체 해제, 정렬 전체 해제, 엑셀 내보내기)과 숨긴 컬럼을 되살리는 목록을 잃는다. 사용자 요청도 "☰ 는 그대로" 였다 | 기각 |
| 헤더 우측에 ☰ 폭만큼 여백을 만들어 둘을 나란히 놓는다 | 두 컨트롤을 모두 보이게 유지 | 컨트롤이 두 개 붙어 있는 상태 자체가 문제였다(무엇을 누르는지 모른다). 여백은 `.slick-header-column` 의 폭 계산과 얽혀 헤더·셀 정렬이 어긋날 위험이 있다 | 기각 |
| 우클릭에서 `plugin.createParentMenu(e, column, menu)` 를 직접 호출 | 숨긴 버튼에 의존하지 않는다 | protected 메서드다. 버튼 핸들러가 먼저 하는 `disposeAllMenus()` 를 우리가 재현해야 하고(빠뜨리면 메뉴가 쌓인다), 위치 계산이 이벤트 target 에 묶여 있어 이벤트 객체를 우리가 만들어 넘겨야 한다. 버전이 올라가면 조용히 깨진다 | 기각 |
| ColumnPicker(우클릭)를 그대로 쓰고 ∨ 만 숨긴다 | 코드 변경이 가장 적다 | 우클릭 메뉴에는 정렬·컬럼 고정이 없다. ∨ 를 숨기면 그 기능에 도달할 방법이 사라진다 | 기각 |

## 근거 (Rationale)

핵심은 **같은 자리를 두 컨트롤이 다투는 상태를 없애는 것**이었고, 그러면 진입점 하나를 옮겨야 한다. 옮길 수 있는 쪽은 ∨ 다 — ☰ 는 그리드 전체 기능이라 위치가 고정적이고, ∨ 는 "그 컬럼" 을 가리키기만 하면 되므로 헤더 우클릭이 그 역할을 그대로 대신할 수 있다. 표 헤더 우클릭은 엑셀·업무 시스템에서 익숙한 조작이기도 하다.

우클릭을 쓰기로 한 순간 `enableColumnPicker` 는 반드시 꺼야 했다. 켜둔 채로 두면 한 번의 우클릭에 메뉴 두 개가 겹쳐 뜬다. 끄는 대가는 없다 — 선택기가 하던 일(컬럼 표시/숨김)은 ☰ 목록이 그대로 갖고 있고, 헤더 메뉴에는 선택기에 없는 정렬·컬럼 고정까지 있다.

`ADR-2026-08-10-custom-control-outside-library-widget` 은 "라이브러리 요소를 CSS 로 숨겨 없앤 것처럼 쓰지 말고, 옵션으로 끌 수 있으면 옵션을 쓴다" 고 정했다. 이번에는 그 예외다. `headerMenu` 옵션에는 버튼만 감추는 항목이 없고(`slickHeaderMenu.js` 의 `_defaults`), `enableHeaderMenu: false` 로 끄면 `column.header.menu.commandItems` 자체가 만들어지지 않아 우클릭으로 열 메뉴가 없어진다. 게다가 여기서는 **숨긴 요소의 박스가 필요하다** — 메뉴 위치 계산이 그 박스를 읽는다. 그래서 "옵션이 없고, 박스는 살려야 한다" 는 두 조건이 겹쳐 `visibility: hidden` 이 유일한 선택이었다.

버튼의 `click()` 을 호출하는 방식은 라이브러리의 원래 경로를 그대로 타는 것이 목적이다. 열려 있던 메뉴 정리, 위치 계산, 포커스 이동, 키보드 내비게이션이 전부 라이브러리 코드에서 처리되므로 우리가 재현할 것이 없다.

## 영향 (Consequences)

- 긍정:
  - 헤더에서 ∨ 가 사라져 컬럼명이 잘리는 인상이 줄고, 우측 상단에 컨트롤은 ☰ 하나만 남는다.
  - 컬럼별 기능(정렬 / 필터·정렬 해제 / 컬럼 숨기기 / 컬럼 고정 / 내용에 맞춰 너비 조정)이 우클릭 한 곳에 모인다.
  - `visibility: hidden` 요소는 마우스 히트테스트에서 빠지므로, 버튼이 있던 컬럼 우측 22px 를 좌클릭하면 이제 정렬이 동작한다 (전에는 버튼이 가로챘다).
  - 브라우저 기본 우클릭 메뉴는 헤더에서 막힌다.
- 트레이드오프/비용:
  - **발견성이 낮아진다.** 우클릭은 눌러봐야 알 수 있다. 데모 가이드(API 요약)와 `gridMenu` prop 주석에 안내를 넣었다.
  - 메뉴가 뜨는 위치는 숨긴 버튼 기준이라 "컬럼 우측 아래" 다. 마우스 커서 위치가 아니다.
  - 행번호(No) 컬럼은 `excludeFromHeaderMenu` 라 버튼이 없고, 따라서 우클릭해도 메뉴가 열리지 않는다(기본 브라우저 메뉴만 막힌다).
- 후속으로 따라오는 결정·제약:
  - **라이브러리 요소를 숨길 때는 그 요소의 박스를 라이브러리가 읽는지 먼저 확인한다.** 읽는다면 `display: none` 이 아니라 `visibility: hidden` 이다. 위치 계산이 조용히 (0,0) 으로 무너진다.
  - **라이브러리 컨트롤의 트리거를 바꿀 때는 원래 핸들러를 재사용한다.** 내부 메서드를 직접 부르는 대신 원래 요소의 이벤트를 발생시키면 정리·위치·포커스 처리를 그대로 물려받는다.
  - **같은 입력(우클릭)을 두 확장이 잡고 있는지 확인한다.** slickgrid-universal 은 `enableColumnPicker` / `enableGridMenu` / `enableHeaderMenu` / `enableContextMenu` 가 전부 기본 `true` 다. 우리 prop 으로 켜는 게 아니라 **꺼야 하는** 구조라는 점을 잊으면 메뉴가 중복으로 뜬다.
  - `grid-menu` prop 은 이 기본값들 때문에 실질적으로 "이미 켜진 것을 다시 켜는" 플래그다. 완전히 감추려면 `:options="{ enableGridMenu: false, enableHeaderMenu: false }"` 로 2층에서 꺼야 한다.
