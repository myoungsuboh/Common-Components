# ADR-2026-07-31-slickgrid-theme-css-variable-override: 테마는 CSS 변수로 덮고, 변수 실존은 var() 참조로 검증

- 기록일: 2026-07-31 11:48
- 상태: 승인됨
- 단계(Origin): dev (execute-dev)
- 관련 spec: 없음
- 관련 plan: 없음

## 맥락 (Context)

`slickgrid-theme-material.css`를 프로젝트 톤에 맞게 바꿀 필요가 있었다. 처음에는 변수명을 짐작해서 `:root`에 나열했는데, 검증해 보니 14개 중 9개가 실제로는 쓰이지 않는 이름이었다(값을 넣어도 아무 일도 일어나지 않는다).

원인은 검증 방법 자체가 틀렸던 것이다. 이 테마 CSS에는 **`:root` 블록이 아예 없다.** 라이트 테마는 전부 `var(--slick-xxx, 라이트기본값)` 형태의 인라인 폴백으로 동작하고, 다크 테마만 `.slick-dark-mode`에 자체 선언을 둔다. 따라서 "선언(`--x:`)이 있는가"는 무의미한 기준이고 "`var(--x`로 참조되는가"가 유일한 기준이다.

또한 일부 값은 변수로 덮을 수 없다고 판단해 CSS 규칙으로 덮으려 했으나 특정도에서 밀렸다. 검색 조건 select의 초록 글자는 테마 규칙이 클래스 5개(`0,5,0`)여서 우리 규칙(클래스4+엘리먼트1 = `0,4,1`)보다 강했다.

## 결정 (Decision)

테마 커스터마이징은 **CSS 변수 오버라이드를 1차 수단으로** 삼는다. 변수를 추가하기 전에 테마 CSS에서 `var(--이름` 참조가 실제로 존재하는지 확인한다. 변수가 없는 값만 CSS 규칙으로 덮고, 그때는 조상 클래스를 하나 더 붙여 특정도를 동률 이상으로 맞춘다(이 파일이 나중에 로드되므로 동률이면 이긴다). 변수 매핑은 `:root`가 아니라 `.sg-grid-wrapper`에 스코프한다.

## 고려한 대안 (Alternatives)

| 대안 | 장점 | 단점 | 채택 여부 |
|------|------|------|-----------|
| CSS 변수 오버라이드 우선 + 필요 시 특정도 동률화 | 테마가 의도한 확장점을 사용, 다크모드가 깨지지 않음, 규칙 구조 변화에 덜 취약 | 변수가 없는 값은 처리 못 함 | 채택 |
| 전부 CSS 규칙으로 덮기 | 변수 존재 여부를 조사할 필요 없음 | 특정도 경쟁에 계속 지고, `!important` 남발로 이어짐 | 기각 |
| `!important` 사용 | 즉시 이김 | 이후 정당한 오버라이드까지 막고 원인 추적이 어려워짐 | 기각 |
| SASS 소스를 직접 빌드해 테마 재생성 | 가장 근본적 | 빌드 파이프라인 추가, 라이브러리 업그레이드마다 재작업 | 기각 |
| `:root`에 변수 선언 | 작성이 간단 | 호스트 프로젝트의 전역을 오염시키고 다른 그리드 인스턴스에 영향 | 기각 (프로젝트 톤 변수 `--sg-*`만 `:root`에 둠) |

## 근거 (Rationale)

변수는 테마가 명시적으로 열어둔 확장점이므로 라이브러리 내부 규칙 구조에 의존하지 않는다. 실제로 검색 조건 select 문제는 `--slick-compound-filter-text-color`와 `--slick-compound-filter-operator-select-border` 두 변수를 덮어 특정도 싸움 없이 해결됐다. 이때 **그 변수가 다른 곳에도 쓰이는지 먼저 확인**했다 — 둘 다 그 select 한 곳에서만 쓰여서 검색 입력칸 글자색에는 영향이 없음을 확인한 뒤 적용했다(입력 글자를 투명하게 만들면 사용자가 타이핑한 내용이 안 보이는 사고가 된다).

다크모드는 커스텀 프로퍼티 해석 규칙 덕분에 안전하다. `.slick-dark-mode` 엘리먼트에는 자기 자신에게 적용된 선언이 있으므로 조상에서 상속되는 우리 값보다 우선한다.

## 영향 (Consequences)

- 긍정: 프로젝트별로 `--sg-*` 값 몇 개만 바꾸면 톤이 전환된다. 다크모드가 깨지지 않는다. `!important`가 없다.
- 트레이드오프/비용: 변수를 추가할 때마다 테마 CSS에서 참조 여부를 조사하는 절차가 필요하다. 변수가 없는 값은 특정도를 계산해야 한다.
- 후속으로 따라오는 결정·제약:
  - **변수를 추가할 때 "선언이 있나"로 판단하지 않는다. `var(--이름` 참조 여부로 확인한다.**
  - 변수를 덮기 전에 그 변수가 다른 요소에도 쓰이는지 확인한다(한 곳에서만 쓰이는지).
  - 특정도로 덮는 규칙에는 왜 그 셀렉터 길이가 필요한지 주석을 남긴다(무심히 짧게 고치면 다시 밀린다). 현재 `input.form-control` 규칙과 연산자 select 규칙이 여기 해당한다.
  - `.slick-cell`에 `display:flex`를 주지 않는다. 에디터·트리 들여쓰기·그룹 행 렌더링이 깨진다. 정렬은 `text-align`으로 한다.
