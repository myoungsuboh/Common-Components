# ADR-2026-07-31-avoid-nested-vuetify-tabs: Vuetify 탭 중첩을 피하고 자체 섹션 전환 사용

- 기록일: 2026-07-31 14:29
- 상태: 승인됨
- 단계(Origin): dev (execute-dev)
- 관련 spec: 없음
- 관련 plan: 없음

## 맥락 (Context)

SlickGrid 데모 페이지의 케이스가 14개까지 늘어 유형별(기본 / 조회·필터 / 선택·CRUD / 편집 / 셀 표현 / 엑셀 / 표시·성능 / 확장 / 가이드)로 묶을 필요가 생겼다.

프로젝트에 이미 `Tab` / `TabContent` 공통 컴포넌트(내부적으로 Vuetify `VTabs` + `VTabsWindow` + `VTabsWindowItem`)가 있어 그대로 재사용했다. MainPage가 바깥 탭으로 이 데모 페이지를 열고, 데모 페이지 안에서 다시 같은 컴포넌트로 섹션 탭을 만드는 **2중 중첩** 구조였다.

그 결과 여러 섹션이 동시에 활성화됐다. 실측하면 `v-window-item--active`가 세 개(가이드·기본·편집)에 동시에 붙어 있었고, 화면에는 "편집 탭인데 기본 케이스 그리드가 함께 보이는" 상태가 됐다. 안쪽 `VTabsWindow`가 바깥 탭과 선택 컨텍스트를 공유하는 것이 원인이다.

그리드가 여러 개 겹쳐 보이는 것 자체도 문제지만, 검증할 때 "보이는 그리드"를 특정할 수 없어 **다른 기능의 테스트 결과까지 계속 오염**시켰다(엉뚱한 그리드를 잡아 오탐을 여러 번 냈다).

## 결정 (Decision)

데모 페이지 안의 섹션 전환은 Vuetify 탭을 중첩하지 않고, 자체 버튼바 + `v-if`로 구현한다. 바깥 MainPage 탭은 기존 `Tab` 컴포넌트를 그대로 사용한다.

```vue
<div class="sg-sections">
  <button v-for="s in SECTIONS" :class="{ 'is-active': section === s.key }" @click="section = s.key">
    {{ s.label }}
  </button>
</div>
<div v-if="section === 'basic'"> ... </div>
```

## 고려한 대안 (Alternatives)

| 대안 | 장점 | 단점 | 채택 여부 |
|------|------|------|-----------|
| 자체 버튼바 + `v-if` | 중첩 문제 없음. `v-if`라 선택한 섹션의 그리드만 생성되는 지연 렌더링 유지. 구현이 단순하고 동작이 예측 가능 | 버튼 스타일을 직접 작성해야 함 | 채택 |
| `Tab`/`TabContent` 중첩 유지 + 격리 방법 탐색 | 기존 공통 컴포넌트 재사용 | Vuetify 내부 provide/inject 동작에 의존해 해결해야 하고, 버전 업그레이드마다 깨질 수 있음. 원인 파악·검증 비용이 큼 | 기각 |
| `VExpansionPanels`(아코디언)로 그룹화 | 중첩 문제 없음 | **접힌 상태에서 그리드를 만들면 컨테이너 폭을 0으로 계산해 컬럼이 찌그러진다.** 이 프로젝트에서 이미 겪은 문제 | 기각 |
| 그룹 없이 한 페이지에 나열 (기존 상태) | 작업 없음 | 케이스 14개가 한 화면에 쏟아져 찾기 어렵고, 모든 그리드가 동시에 생성되어 무겁다 | 기각 |
| 라우터로 섹션 분리 | 주소로 공유 가능 | 이 저장소는 라우터를 쓰지 않는다(단일 페이지 + 탭 구조). 구조 변경 범위가 큼 | 기각 |

## 근거 (Rationale)

`v-if`는 중첩 문제를 없애면서 **지연 렌더링이라는 원래의 요구도 그대로 만족**한다. 이 점이 중요한 이유는, 숨겨진 컨테이너에서 SlickGrid을 생성하면 사용 가능한 폭을 0으로 계산해 컬럼이 찌그러지기 때문이다(아코디언을 기각한 이유이기도 하다). `v-if`는 아예 마운트하지 않으므로 그 문제가 발생하지 않는다.

공통 `Tab` 컴포넌트를 고치는 선택지도 있었지만, 이건 **데모 페이지 한 곳의 문제**이지 `Tab` 컴포넌트 자체의 결함이라고 단정하기 어렵다(단일 계층으로 쓸 때는 정상 동작한다). 다른 화면에 영향을 주는 공통 컴포넌트 수정보다 사용처에서 해결하는 편이 안전하다.

## 영향 (Consequences)

- 긍정: 각 섹션이 자기 케이스만 표시한다(실측 확인). 선택한 섹션의 그리드만 생성된다. 검증 시 "보이는 그리드"가 명확해져 테스트 신뢰도가 올라갔다.
- 트레이드오프/비용: 데모 페이지에 버튼바 스타일 약 30줄이 추가됐다. 공통 `Tab` 컴포넌트와 시각적으로 다르다.
- 후속으로 따라오는 결정·제약:
  - **`Tab`/`TabContent`를 중첩해서 쓰지 않는다.** 필요하면 이 방식(버튼바 + `v-if`)을 쓴다.
  - 그리드를 **접힌/숨겨진 컨테이너 안에서 마운트하지 않는다.** 폭을 0으로 계산한다. 지연 마운트(`v-if`)를 쓰거나, 보여진 뒤 `resize()`를 호출한다.
  - 공통 `Tab` 컴포넌트를 중첩 지원하도록 개선하는 것은 별도 과제로 남긴다(현재 단일 계층 사용에는 문제 없음).
