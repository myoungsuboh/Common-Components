# ADR-2026-07-31-library-extension-point-workarounds: 라이브러리 확장점 우회 방식

- 기록일: 2026-07-31 14:29
- 상태: 승인됨
- 단계(Origin): dev (execute-dev)
- 관련 spec: 없음
- 관련 plan: 없음

## 맥락 (Context)

기능을 추가할 때 slickgrid-universal이 제공하는 확장점을 그대로 쓰려 했으나, 여러 곳에서 "옵션은 존재하는데 동작하지 않거나, 우리 요구를 만족시킬 수 없는" 상황을 반복해서 만났다. 공통적으로 **에러가 나지 않고 조용히 아무 일도 일어나지 않는다**는 점이 문제였다 — 원인을 찾는 데 매번 소스를 직접 읽어야 했다.

실제로 확인한 사례들이다.

| 확장점 | 문제 | 확인 방법 |
|--------|------|-----------|
| `gridOptions.getItemMetadata` | slickgrid-vue가 어디에도 연결하지 않는 **죽은 옵션**. 코어는 `dataView.getItemMetadata`만 읽는다 | dist 전체 검색 → 참조 0건 |
| `Constants.VALIDATION_REQUIRED_FIELD` | 필수입력 메시지가 `'Field is required'` **정적 상수**. locales로 한글화할 경로가 없다 | `constants.js` 확인 |
| footer row (합계 행) | 라이브러리가 **빈 셀만** 만들어준다. 내용은 직접 채워야 한다 | `getFooterRowColumn()` 반환값 확인 |
| `draggableGrouping.dropPlaceHolderTextKey` | `enableTranslate: true`일 때만 번역된다. 우리는 i18next 없이 locales만 쓰므로 영어가 남는다 | 확장 소스의 조건문 확인 |
| 드래그 그룹핑 | 컬럼에 `grouping` 객체가 없으면 해당 컬럼을 **조용히 무시** | `if (col.grouping && !isEmptyObject(col.grouping))` |

## 결정 (Decision)

확장점이 없거나 동작하지 않으면 우회하되, 아래 세 가지 규칙을 지킨다.

1. **우회하기 전에 라이브러리 소스에서 실제 동작을 확인한다.** 문서나 옵션 이름만 보고 판단하지 않는다.
2. **라이브러리 전역 상태(정적 상수 등)는 변형하지 않는다.** 대신 우리 레이어에서 같은 결과를 만든다.
3. **라이브러리가 DOM에 부여한 클래스·속성은 지우지 않고 추가만 한다.**

구체적으로:
- 합계 행 → `getFooterRowColumn()`으로 셀을 얻어 `textContent`를 채우고, 클래스는 `classList.add/remove`로만 조작한다.
- 필수입력 메시지 → `editor.required`를 쓰지 않고, 필수검사를 포함한 `editor.validator`를 합성해 한글 메시지를 낸다.
- 행/셀 메타데이터 → 그리드 생성 후 `dataView.getItemMetadata`를 감싼다(기존 메타가 있으면 그것을 우선).
- 그룹핑 → `groupable`이 켜지면 컬럼 빌더가 기본 `grouping`을 자동 생성한다.

## 고려한 대안 (Alternatives)

| 대안 | 장점 | 단점 | 채택 여부 |
|------|------|------|-----------|
| 우회 + 위 3규칙 | 요구를 만족하면서 부작용을 통제. 라이브러리 업그레이드 시 영향 범위가 우리 코드에 국한 | 라이브러리 내부 구조에 의존하므로 메이저 업그레이드 때 재검증 필요 | 채택 |
| `Constants.VALIDATION_REQUIRED_FIELD`를 직접 덮어쓰기 | 한 줄로 해결 | 임포트한 모듈의 전역 상태 변형. 같은 앱의 다른 그리드·다른 컴포넌트까지 영향 | 기각 |
| 라이브러리에 PR을 보내 고치기 | 근본적 | 반영·릴리스까지 대기 불가 (지금 쓰는 프로젝트가 있음) | 기각 (장기 과제) |
| 해당 기능을 포기 | 유지보수 부담 없음 | 합계 행·한글 메시지는 국내 업무화면의 기본 요구라 포기 불가 | 기각 |
| 합계를 그리드 밖 별도 div로 그리기 | 라이브러리와 무관 | 컬럼 폭·가로 스크롤과 동기화가 안 되어 어긋난다 | 기각 |

## 근거 (Rationale)

세 규칙은 모두 이번 작업에서 실제로 사고를 낸 뒤 세운 것이다.

3번 규칙(클래스 보존)은 특히 값비싼 교훈이었다. 합계 셀에 `cell.className = '...'`로 대입했더니 SlickGrid이 붙여둔 `slick-footerrow-column l0 r0`가 지워졌다. 이 클래스들이 셀의 위치와 너비를 담당하므로 합계 행 레이아웃이 통째로 깨졌는데, **에러도 없고 셀은 존재해서** 원인을 찾는 데 시간이 걸렸다. 같은 이유로 헤더 컬럼에 padding을 더했을 때도 헤더와 셀이 컬럼당 18px씩 어긋났다(`box-sizing: content-box`).

2번 규칙(전역 변형 금지)은 이 컴포넌트가 여러 프로젝트에 투입된다는 목표에서 나온다. 임포트한 상수를 바꾸면 그 프로젝트의 다른 그리드까지 영향을 받고, 원인을 추적할 단서가 남지 않는다. 필수검사를 validator로 합성하면 부작용이 없고, `requiredMessage`로 컬럼별 문구까지 지정할 수 있어 오히려 기능이 늘었다.

## 영향 (Consequences)

- 긍정: 합계 행·한글 메시지·행 단위 잠금·그룹핑이 모두 동작한다. 부작용이 우리 코드 안에 머문다.
- 트레이드오프/비용: 라이브러리 내부 구현(클래스명, 메서드 이름, 조건문)에 의존하는 지점이 늘었다. 메이저 업그레이드 시 재검증이 필요하다.
- 후속으로 따라오는 결정·제약:
  - **`cell.className` / `element.className` 에 대입하지 않는다.** `classList` 로만 조작한다.
  - **헤더/셀 요소에 padding·width를 추가하지 않는다.** SlickGrid이 px로 계산해 둔 크기와 어긋난다. 내부 요소(`.slick-column-name` 등)를 조정한다.
  - **`editor.required` 를 쓰지 않는다.** 영문 메시지가 나온다. `required` 축약이 validator를 합성한다.
  - 새 기능을 붙일 때 옵션이 동작하지 않으면 **먼저 `node_modules` 소스에서 그 옵션의 참조 여부를 확인**한다. 죽은 옵션일 수 있다.
  - 이 우회 지점들은 코드에 이유를 적은 주석을 함께 둔다(무심히 "정리"하면 조용히 깨진다).
