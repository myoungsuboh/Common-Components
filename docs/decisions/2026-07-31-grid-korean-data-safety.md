# ADR-2026-07-31-grid-korean-data-safety: 한글·국내 업무 데이터 안전 규약

- 기록일: 2026-07-31 11:48
- 상태: 승인됨
- 단계(Origin): dev (execute-dev)
- 관련 spec: 없음
- 관련 plan: 없음

## 맥락 (Context)

국내 업무 화면은 불리언 값을 `'Y'`/`'N'` 문자열로 저장하는 관행이 넓게 쓰인다. 축약 타입 `yn`을 만들면서 편집 에디터로 자연스러워 보이는 `Editors.checkbox`를 배정했는데, 이 에디터는 **boolean(`true`/`false`)을 저장**한다. `'Y'`/`'N'` 필드에 boolean이 들어가면 포맷터가 값을 읽지 못하고, 서버로도 타입이 다른 값이 전송된다. 화면상 즉시 드러나지 않고 저장 후에야 문제가 되는 종류의 결함이다.

엑셀 내보내기 쪽에서도 한글 깨짐 요구가 있었다. `excelExportOptions.format`은 `'xls'`와 `'xlsx'`를 받는다.

## 결정 (Decision)

- `yn` 타입의 편집 에디터를 `Editors.singleSelect`로 한다(값이 문자열로 유지된다). 필터용 코드셋과 편집용 코드셋을 분리한다 — 필터는 "전체"에 해당하는 빈 값이 필요하지만 편집에는 있으면 안 된다.
- 엑셀 내보내기 `format`을 `'xlsx'`로 **명시적으로 고정**한다. `exportWithFormatter: true`로 화면 포맷(코드값이 아닌 명칭)을 그대로 내보낸다.
- CSV 내보내기는 기본 제공하지 않는다.

## 고려한 대안 (Alternatives)

| 대안 | 장점 | 단점 | 채택 여부 |
|------|------|------|-----------|
| `yn` 편집을 `Editors.singleSelect` | 값이 `'Y'`/`'N'` 문자열로 유지됨 | 체크박스보다 클릭 수가 많음 | 채택 |
| `yn` 편집을 `Editors.checkbox` | UI가 직관적 | **boolean을 저장해 문자열 필드 타입을 깨뜨림** | 기각 |
| `yn`을 checkbox로 두고 저장 시 변환 계층 추가 | UI 직관성 + 타입 유지 | 변환 지점이 숨어 있어 추적이 어렵고, 별도 `checkbox` 타입과 역할이 겹침 | 기각 |
| `format: 'xlsx'` 명시 고정 | ZIP + UTF-8 XML 구조라 한글이 안전 | 없음(라이브러리 기본값과 동일) | 채택 |
| `format` 미지정(기본값 의존) | 코드가 짧음 | 기본값은 현재 `'xlsx'`지만, 이후 프로젝트에서 options로 `'xls'`로 바꾸면 조용히 한글이 깨짐 | 기각 |
| `text-export`로 CSV 제공 | CSV 요구에 대응 | CSV는 UTF-8 BOM이 없으면 엑셀에서 한글이 깨져 별도 처리가 필요, 패키지 추가 | 기각(현 시점 범위 밖) |

## 근거 (Rationale)

`yn` 문제는 "동작하는 것처럼 보이지만 데이터를 오염시키는" 유형이라 기본값 자체가 안전해야 한다. 눌러서 바꾸는 체크박스 UI가 필요한 경우는 별도의 `checkbox` 타입으로 분리하고, 그쪽에서 `checkedValue`/`uncheckedValue`로 저장값을 지정하게 해서(`'Y'`/`'N'` 지정 가능) 두 요구를 모두 만족시켰다.

엑셀 `format`은 라이브러리 기본값이 이미 `'xlsx'`임을 소스에서 확인했지만(`DEFAULT_EXPORT_OPTIONS`), 그래도 명시했다. 이 컴포넌트는 여러 프로젝트에 투입되고 2층(options 통과)으로 옵션을 자유롭게 덮을 수 있으므로, 누군가 `'xls'`로 바꿔 한글이 깨지는 경로가 열려 있다. 명시와 주석이 그 경로에 대한 경고 역할을 한다. `'xls'`는 레거시 포맷으로 인코딩 정보를 담지 않아 한글이 깨진다.

엑셀 업로드는 기존 `ExcelUploader` 컴포넌트를 그대로 재사용했다. 그쪽이 이미 `codepage: 949`로 레거시 `.xls` 한글을 처리하고 있고, 그래도 깨질 경우 `import 'xlsx/dist/cpexcel'`이 필요하다는 사실이 해당 파일 주석에 남아 있다.

## 영향 (Consequences)

- 긍정: `'Y'`/`'N'` 필드가 편집 후에도 문자열로 유지된다. 엑셀 파일·시트명·내용의 한글이 깨지지 않는다. 코드 컬럼은 코드값이 아니라 명칭으로 내보내진다.
- 트레이드오프/비용: `yn` 편집이 체크박스보다 클릭 수가 많다. CSV를 원하는 프로젝트는 별도 작업이 필요하다.
- 후속으로 따라오는 결정·제약:
  - **`yn` 타입 에디터를 `Editors.checkbox`로 되돌리지 않는다.** 상호작용 체크박스가 필요하면 `type: 'checkbox'`를 쓴다.
  - `excelExportOptions.format`을 `'xls'`로 바꾸지 않는다.
  - CSV를 추가할 때는 `text-export`의 UTF-8 BOM 옵션을 반드시 켠다.
  - 필터용/편집용 코드셋 분리 구조를 유지한다(편집 드롭다운에 빈 값이 섞이면 데이터에 빈 문자열이 저장된다).
