# ADR-2026-08-10-custom-control-outside-library-widget: 커스텀 컨트롤은 위젯 밖에 둔다

- 기록일: 2026-08-10 10:45
- 상태: 승인됨
- 단계(Origin): dev (execute-dev)
- 관련 spec: 없음
- 관련 plan: 없음

## 맥락 (Context)

"페이지에서 보여줄 개수를 버튼이 아닌 선택 및 입력 가능하도록" 이라는 요구가 들어왔다. DevExtreme 기본 페이지크기 선택기는 `[20][50][100][500]` 버튼이라 목록에 없는 값(35 등)을 쓸 수 없고, 항목이 늘면 자리를 많이 차지한다.

DevExtreme 페이저에는 이 컨트롤의 모양을 바꾸는 옵션이 없다. `showPageSizeSelector` 는 표시 여부만 정하고, 드롭다운 형태는 좁은 화면에서 compact(`dx-light-mode`) 로 바뀔 때만 자동으로 나타난다(적응형 계산에 묶여 있어 따로 지정할 수 없다).

그래서 컨트롤을 우리가 만들어야 하는데, **어디에 놓을지**가 문제였다. 페이저는 DevExtreme 이 Inferno 로 렌더하는 영역이고, 페이지를 이동하면 다시 그려진다.

## 결정 (Decision)

1. **우리 컨트롤을 위젯 안에 넣지 않는다.** 래퍼(`.dxg-wrapper`)가 소유한 요소로 만들고, `position: absolute` 로 페이저 행에 겹쳐 놓는다.
2. **DevExtreme 기본 선택기는 옵션으로 끈다**(`showPageSizeSelector: false`). CSS 로 숨기지 않는다 — 숨긴 요소도 적응형 계산에 폭으로 들어간다.
3. **배치는 페이지 번호가 없는 쪽으로 한다.** 정렬 `left` 면 번호가 왼쪽이므로 컨트롤은 오른쪽, `center`/`right` 면 왼쪽. 이미 중앙 정렬에서 `.dx-page-sizes`/`.dx-info` 를 절대배치하던 것과 같은 슬롯 규칙을 쓴다.
4. **컨트롤 자체는 `<input list>` + `<datalist>` 로 만든다.** 선택과 자유 입력을 하나의 기본 컨트롤로 처리한다.
5. **Vuetify 컴포넌트를 쓰지 않는다.** 컴포넌트 폴더를 Vuetify 비의존으로 격리한다는 기존 결정에 따라, 겉모습만 CSS 로 Vuetify 입력창 톤에 맞춘다.
6. 빈 영역이 페이저 클릭을 가로채지 않도록 컨테이너는 `pointer-events: none`, 실제 컨트롤만 `auto` 로 되돌린다.

## 고려한 대안 (Alternatives)

| 대안 | 장점 | 단점 | 채택 여부 |
|------|------|------|-----------|
| 래퍼가 소유한 요소를 페이저 행에 겹치기 | 라이브러리가 다시 그려도 영향이 없다. 우리 DOM 이므로 Vue 반응성·이벤트가 그대로 동작한다 | 페이저 행 높이에 맞춘 위치 값을 하나 갖는다 | 채택 |
| 페이저 안에 DOM 을 직접 넣기 (append / Teleport) | 페이저와 한 줄에 자연스럽게 배치된다 | 페이저는 Inferno 컴포넌트라 페이지 이동 시 다시 그려지며 외부 자식을 지운다. MutationObserver 로 다시 붙이는 식의 방어가 필요해진다 | 기각 |
| 페이저 전체를 우리가 만든 컴포넌트로 교체 (SlickGrid 방식) | 완전한 제어. 모든 옵션을 자유롭게 만들 수 있다 | 페이지 이동·건수 변경·적응형·접근성을 전부 다시 구현해야 한다. DevExtreme 페이저가 이미 잘 하는 일을 버리게 된다 | 기각 (SlickGrid 은 커스텀 페이지네이션 확장점이 있어서 그렇게 했지만, 여기서는 이득이 없다) |
| 그리드 위쪽 툴바에 "표시 개수" 를 두기 | 배치가 단순하고 겹침 위험이 없다 | 요구가 기존 버튼 자리를 대체하는 것이었다. 페이지 관련 조작이 위아래로 흩어진다 | 기각 |
| `<select>` + 별도 숫자 입력칸 | 브라우저 지원이 확실 | 컨트롤이 둘이라 조작이 번거롭고 자리도 더 차지한다 | 기각 |
| 직접 만든 드롭다운 | 모양을 완전히 통제 | 키보드 조작·포커스 관리·접근성을 직접 구현해야 한다. 이득 대비 비용이 크다 | 기각 |

## 근거 (Rationale)

핵심 근거는 **소유권 분리**다. 라이브러리가 다시 그리는 영역에 우리 DOM 을 넣으면 "언제 지워지는지" 를 계속 신경 써야 하고, 그 실패는 조용하다(컨트롤이 사라져도 오류가 나지 않는다). 이 저장소에서 이미 비슷한 교훈이 있었다 — 합계 셀에 `className` 을 대입해 라이브러리가 붙인 클래스를 지운 사고, 그리고 SlickGrid 전체선택 체크박스를 라이브러리 헤더 안에 직접 주입하며 겪은 문제들이다.

절대배치가 위험해 보일 수 있지만, 이미 중앙 정렬에서 같은 기법을 검증했고(겹침 없음, compact 전환 시 해제) 배치 규칙도 재사용한다. 무엇보다 **컨트롤이 우리 DOM 이므로 라이브러리 업데이트에 영향받지 않는다.**

기본 선택기를 CSS 로 숨기지 않고 옵션으로 끈 것도 이유가 있다. 페이저의 적응형 계산은 `.dx-page-sizes` 의 computed width 를 읽으므로, `display: none` 으로 숨긴 요소도 계산에 참여하거나(0 으로) 판정을 흔들 수 있다. 옵션으로 끄면 요소가 아예 만들어지지 않아 계산이 깔끔하다.

## 영향 (Consequences)

- 긍정: 목록에 없는 값(35)도 쓸 수 있고, 범위를 벗어나면 min/max 로 잘라 되돌린다. 정렬 3종 모두에서 번호·정보와 겹치지 않음을 확인했다(세로 중심 오차 1px). 페이지를 이동해도 컨트롤이 유지된다.
- 트레이드오프/비용:
  - 페이저 행 높이에 맞춘 값(`height: 56px`)을 CSS 에 갖는다. 테마를 바꾸면 확인이 필요하다.
  - `<datalist>` 는 브라우저마다 드롭다운 표시가 조금 다르다(값은 동일하게 동작).
- 후속으로 따라오는 결정·제약:
  - **라이브러리 위젯 내부에 우리 DOM 을 넣지 않는다.** 필요하면 래퍼가 소유한 요소를 그 자리에 겹친다.
  - **라이브러리 요소를 CSS 로 숨겨 없앤 것처럼 쓰지 않는다.** 그 요소의 크기를 라이브러리가 읽을 수 있다. 옵션으로 끌 수 있으면 옵션을 쓴다.
  - **입력을 거절·보정할 때는 확정 값을 DOM 에 직접 되돌린다.** `:value` 바인딩만 믿으면 보정 값이 직전 값과 같을 때 ref 가 바뀌지 않아 Vue 가 DOM 을 되돌리지 않고, 사용자가 넣은 잘못된 값(빈 문자열 등)이 남는다.
  - 페이저 요소를 CSS 로 숨길 때는 **그 안에 다른 기능이 함께 들어 있는지 확인한다.** `.dx-page-indexes` 안에는 번호뿐 아니라 이전/다음 버튼도 있어서, 통째로 숨기면 이동 수단이 사라진다.
