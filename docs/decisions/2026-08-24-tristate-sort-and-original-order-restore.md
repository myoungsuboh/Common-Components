# ADR-2026-08-24-tristate-sort-and-original-order-restore: 3단계 정렬과 원래 순서 복원

- 기록일: 2026-08-24 06:45
- 상태: 승인됨
- 단계(Origin): dev (execute-dev)
- 관련 spec: 없음
- 관련 plan: 없음

## 맥락 (Context)

컬럼 헤더를 좌클릭하면 오름차순 → 내림차순 두 상태만 무한히 반복했다. 정렬을 되돌릴 방법이 헤더 메뉴의 "정렬 해제" 뿐이어서, 정렬을 걸어본 뒤 원래 순서를 다시 보려면 메뉴를 열어야 했다. "세 번째 클릭에서 초기 정렬 값으로 돌아가고 정렬 화살표도 사라져야 한다" 는 요구가 들어왔다.

라이브러리 소스를 확인한 결과 두 가지가 걸려 있었다.

1. 3단계 자체는 옵션이 있다. `tristateMultiColumnSort` (기본값 `false`). `slickGrid.js` 의 `setupColumnSort` 는 이 옵션이 켜져 있을 때 "이미 정렬 중이던 컬럼이 다시 오름차순으로 돌아오려는 순간" 그 컬럼을 `sortColumns` 에서 빼고 `setSortColumns()` 로 아이콘까지 지운다.

2. **정렬이 풀려도 행 순서는 되돌아가지 않는다.** `SortService.handleLocalOnSort` 는 빈 정렬로 `dataView.sort(sortComparers)` 를 호출하는데, `sortComparer` 는 `sortColumn.sortCol` 이 없으면 `undefined` 를 돌려주고 `sortComparers` 는 그것을 `neutral(0)` 로 바꾼다. 비교가 항상 0이면 정렬은 순서를 바꾸지 않으므로, 화살표만 사라지고 행은 직전 내림차순 순서에 그대로 남는다.

라이브러리 자신도 이 문제를 알고 있어서, "정렬 해제" 명령(`clearSortByColumnId`) 과 `clearSorting()` 은 남은 정렬이 없을 때 `sortLocalGridByDefaultSortFieldId()` 를 호출한다 — `defaultColumnSortFieldId ?? datasetIdPropertyName ?? 'id'` 기준 오름차순 재정렬이다.

## 결정 (Decision)

1. **`tristateMultiColumnSort: true`** 를 BASE_OPTIONS 에 넣는다. 오름 → 내림 → 해제와 아이콘 제거는 라이브러리가 한다.
2. **해제 단계에서 원래 순서로 되돌리는 것은 래퍼가 한다.** `@onSort` 에서 남은 정렬이 0개면 `sortService.sortLocalGridByDefaultSortFieldId()` 를 호출한다 (`SlickGrid.vue` `handleSort`). 라이브러리의 "정렬 해제" 명령과 같은 경로이므로 두 방법의 결과가 어긋나지 않는다.
3. **서버 모드(fetchData)에서는 아무 것도 하지 않는다.** 정렬이 풀리면 `sorters: []` 로 서버에 재조회되므로 서버가 준 원래 순서가 그대로 온다. 여기서 로컬 재정렬까지 하면 조회가 두 번 나간다.
4. **`multiColumnSort: false` — 단일 정렬을 기본으로 한다.** (기존 값 `true` 에서 변경)
5. 복원 기준이 행 고유 키 오름차순이라는 점을 prop 주석과 데모 가이드에 적고, 다른 기준이 필요하면 2층에서 `defaultColumnSortFieldId` 로 지정하게 안내한다.

## 고려한 대안 (Alternatives)

| 대안 | 장점 | 단점 | 채택 여부 |
|------|------|------|-----------|
| `tristateMultiColumnSort` 로 3단계, 해제 복원은 래퍼가 처리 | 클릭 상태 관리·아이콘 제거를 라이브러리가 전부 한다. 우리 코드는 "남은 정렬 0개면 복원" 한 줄 | 복원 호출이 라이브러리의 정렬(빈 정렬) 뒤에 한 번 더 정렬을 돌린다 | 채택 |
| 3단계 토글을 래퍼가 직접 구현 (클릭 횟수 추적 후 clearSorting) | 복원 시점을 완전히 통제 | 컬럼별 상태·아이콘·다중 정렬을 우리가 다시 만들어야 한다. 라이브러리에 이미 있는 기능을 중복 구현 | 기각 |
| 데이터 로드 순서를 따로 기억해 그 순서로 복원 (WeakMap 에 원래 인덱스) | "받은 순서" 를 정확히 복원한다. 키 순서와 로드 순서가 달라도 맞다 | 데이터가 바뀔 때마다(v-model 갱신·서버 재조회·행 추가) 인덱스를 다시 만들어야 하고, 새로 추가된 행의 자리를 정하는 규칙이 또 필요하다. 라이브러리의 "정렬 해제" 와 결과가 달라져 같은 그리드에서 두 복원 방식이 생긴다 | 기각 |
| 해제 시 아무 것도 하지 않는다 (아이콘만 사라짐) | 코드 없음 | 요구가 "초기 정렬 값으로 돌아가야 해" 였다. 화살표는 없는데 순서는 내림차순인 상태가 오히려 더 헷갈린다 | 기각 |
| `multiColumnSort: true` 유지 (누적 정렬 + 3단계) | 여러 컬럼 정렬 기능을 잃지 않는다 | tristate 에서는 shift 없이 평범한 클릭이 누적된다. 1차 정렬 컬럼 값이 고유하면 2차 정렬은 화면을 전혀 바꾸지 않아 "클릭했는데 정렬이 안 된다" 로 읽힌다 (실측으로 확인) | 기각 — 2층에서 켤 수 있게 남겨둠 |

## 근거 (Rationale)

3단계 토글은 이미 라이브러리에 있으므로 그것을 쓰는 게 맞다. 우리가 채워야 하는 구멍은 **"정렬 없음" 이 곧 "원래 순서" 가 아니라는 점** 하나였다. 그 구멍을 라이브러리가 자기 "정렬 해제" 명령에서 쓰는 함수(`sortLocalGridByDefaultSortFieldId`, `.d.ts` 에 public 으로 선언되어 있다)로 메우면, 헤더 3번 클릭과 헤더 메뉴의 "정렬 해제" 와 `ref.clearSorting()` 세 경로가 모두 같은 결과를 낸다. 복원 방식을 우리가 따로 만들면 이 세 경로가 서로 다른 순서를 만든다.

`multiColumnSort` 를 끈 것은 요구 범위를 지키기 위한 판단이다. tristate 는 다중 정렬과 조합될 때 "평범한 클릭 = 누적" 으로 동작이 바뀐다(라이브러리 코드에서 shift/meta 를 보지 않는다). 실제로 데모에서 이름 → 부서를 클릭해보니 화살표가 2개 붙고 순서는 이름 정렬과 똑같았다 — 이름 값이 고유해서 2차 정렬이 아무 영향을 못 준 것이다. 사용자 입장에서는 "부서를 눌렀는데 안 먹는다" 로 보인다. 반면 shift+클릭 다중 정렬은 이 컴포넌트 어디에도 안내된 적이 없는 기능이었다. 그래서 눈에 보이는 동작(한 번에 한 컬럼)을 그대로 유지하고, 다중 정렬은 2층 옵션으로 남겼다.

## 영향 (Consequences)

- 긍정:
  - 헤더 좌클릭이 오름 → 내림 → 해제로 돌고, 해제 시 행 순서와 정렬 화살표가 모두 초기 상태로 돌아간다 (로컬·서버 모드 모두 실측 확인).
  - 정렬을 되돌리려고 메뉴를 열 필요가 없다.
  - 서버 모드는 클릭당 요청 1건을 유지한다 (해제 클릭도 `sorters: []` 로 1건).
- 트레이드오프/비용:
  - **shift+클릭 다중 정렬이 기본에서 사라진다.** `:options="{ multiColumnSort: true }"` 로 되살릴 수 있고, 그때는 평범한 클릭이 누적 정렬이 된다.
  - 로컬 모드에서 해제 클릭은 정렬을 두 번 돈다 (라이브러리의 빈 정렬 + 우리 복원 정렬). 빈 정렬은 비교가 항상 0이라 사실상 비용이 없지만, 10만 행에서는 두 번의 `Array.sort` 가 돌아간다.
  - 복원 기준이 행 고유 키 오름차순이므로, 서버가 키와 다른 순서로 내려주는 목록에서는 `defaultColumnSortFieldId` 를 지정해야 "받은 순서" 와 같아진다.
- 후속으로 따라오는 결정·제약:
  - **"정렬을 비우면 원래 순서로 돌아간다" 고 가정하지 않는다.** 비교 함수가 neutral 을 돌려주는 정렬은 순서를 바꾸지 않는다. 되돌리려면 기준 필드로 다시 정렬해야 한다.
  - **라이브러리가 같은 일을 하는 내부 경로를 이미 갖고 있는지 먼저 찾는다.** 여기서는 "정렬 해제" 명령이 쓰는 함수를 그대로 재사용해 세 경로의 결과를 일치시켰다.
  - **옵션 하나를 켤 때 그 옵션이 다른 옵션의 의미를 바꾸는지 확인한다.** `tristateMultiColumnSort` 는 `multiColumnSort` 의 클릭 동작(교체 → 누적)을 바꾼다.
