# ADR-2026-07-31-grid-cell-interaction-protocol: 셀 상호작용 프로토콜 (data-sg-* 규약)

- 기록일: 2026-07-31 11:48
- 상태: 승인됨
- 단계(Origin): dev (execute-dev)
- 관련 spec: 없음
- 관련 plan: 없음

## 맥락 (Context)

셀에 버튼·체크박스·이미지·첨부파일 같은 요소가 들어가고, 클릭하면 이벤트를 돌려받아야 한다는 요구가 있었다("이 부분을 잘 해야 활용하기 편할 것"). SlickGrid은 가상 렌더링으로 셀 DOM을 계속 생성·제거하므로 Vue 컴포넌트를 셀에 직접 마운트하면 생명주기 관리가 복잡하고 비용이 크다. 한편 SlickGrid 포맷터는 문자열 외에 `HTMLElement`·`DocumentFragment`도 반환할 수 있다.

또한 체크박스처럼 상태가 있는 요소는 클릭 시 **데이터를 갱신하지 않으면** 스크롤·정렬·필터로 셀이 다시 그려지는 순간 값이 원래대로 돌아간다.

## 결정 (Decision)

셀 상호작용을 **DOM data 속성 규약**으로 정의한다.

- `data-sg-action="<액션명>"` → 클릭 시 `on-cell-action` 이벤트 (`{ action, row, item, column, target }`)
- `data-sg-toggle="<필드명>"` → 클릭 시 데이터를 갱신하고 `on-cell-toggle` 이벤트 (`{ field, checked, value, row, item, column }`)

포맷터는 `HTMLElement`를 직접 만들어 반환한다(HTML 문자열을 만들지 않는다). 래퍼의 클릭 핸들러가 클릭 지점에서 위로 올라가며 이 속성을 찾아 분기하고, **속성을 찾으면 행 클릭 이벤트는 발생시키지 않는다.**

## 고려한 대안 (Alternatives)

| 대안 | 장점 | 단점 | 채택 여부 |
|------|------|------|-----------|
| data 속성 규약 + HTMLElement 반환 포맷터 | 가상 렌더링과 충돌 없음, 사용자가 만든 커스텀 포맷터도 속성만 붙이면 참여 가능, 비용이 거의 없음 | 규약을 문서로 알려야 함, 타입 안전성 없음 | 채택 |
| 셀마다 Vue 컴포넌트 마운트 | Vue 컴포넌트를 그대로 재사용 가능 | 가상 스크롤로 셀이 계속 생성·제거되어 마운트/언마운트 비용이 큼, 대용량에서 성능 저하 | 기각 |
| HTML 문자열을 반환하는 포맷터 | 작성이 짧음 | 새니타이즈 문제(값에 태그가 섞이면 XSS), 이벤트 연결이 별도로 필요 | 기각 |
| 컬럼별 `onClick` 콜백을 컬럼 정의에 직접 넣기 | 사용법이 직관적 | 이벤트 소스가 컬럼 정의와 컴포넌트 이벤트로 이원화되어 흐름 추적이 어려움 | 기각 |
| 체크박스 갱신을 `dataView.updateItem()`으로 | 라이브러리 표준 경로 | `id` 속성을 요구하므로 id 없는 데이터에서 실패 | 기각 (item 직접 변경 + `invalidateRow` 채택) |

## 근거 (Rationale)

data 속성 규약은 **확장 지점이 하나로 모인다**는 점이 핵심이다. 내장 `button`/`checkbox` 타입뿐 아니라 사용자가 직접 작성한 포맷터도 `el.dataset.sgAction = 'detail'` 한 줄만 붙이면 동일한 이벤트로 올라온다. 즉 새로운 셀 컴포넌트를 추가할 때 래퍼를 고칠 필요가 없다.

버튼 클릭과 행 클릭의 격리는 실사용에서 반드시 필요하다. 수정 버튼을 눌렀는데 행 상세까지 열리면 오동작이다. 실측으로 버튼 클릭 시 `on-cell-action`만 발생하고 `on-row-click`은 발생하지 않음을 확인했다.

체크박스 데이터 갱신은 `item[field] = value` 직접 변경 후 `invalidateRow`/`render`로 처리했다. `item`은 dataset 배열 안의 객체와 같은 참조라서 `v-model`에도 반영되고, `dataView.updateItem()`이 요구하는 `id` 속성이 없는 데이터에서도 동작한다. 실측으로 토글 후 스크롤 재렌더링에도 값이 유지됨을 확인했다.

## 영향 (Consequences)

- 긍정: 버튼/체크박스/이미지/첨부/링크가 동작하고, 커스텀 컴포넌트 셀도 래퍼 수정 없이 이벤트를 받는다. 가상 렌더링과 충돌하지 않는다.
- 트레이드오프/비용: 규약이 문자열 기반이라 오타를 컴파일 타임에 못 잡는다. Vue 컴포넌트(예: Vuetify 버튼)를 셀에 그대로 넣을 수는 없고 DOM으로 만들어야 한다.
- 후속으로 따라오는 결정·제약:
  - **`data-sg-action` / `data-sg-toggle` 속성명은 공개 API로 취급한다.** 바꾸면 사용처의 커스텀 포맷터가 조용히 동작을 멈춘다.
  - 액션 요소를 찾으면 행 클릭을 emit하지 않는다(이 순서를 바꾸면 오동작).
  - 상태를 가진 셀 요소를 추가할 때는 반드시 데이터를 갱신한다. 갱신하지 않으면 재렌더링 시 값이 되돌아간다.
  - 이벤트 payload에서 컬럼은 `cell` 인덱스로 조회하지 않고 SlickGrid이 준 `column`을 쓴다. 체크박스 선택 컬럼이 앞에 붙거나 사용자가 컬럼 순서를 바꾸면 인덱스가 어긋난다.
  - `type: 'button'`/`'image'` 컬럼은 데이터가 아니므로 엑셀 내보내기에서 제외한다.
